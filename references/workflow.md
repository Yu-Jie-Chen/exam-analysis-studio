# 工作流程

四个动作来自《高报学生试卷分析操作流程 V1.3》：**核对 → 定位 → 整理 → 备课**。
本文件把每一步拆成可以照着做的动作，以及做错的典型样子。

## Phase 0 · 收料

见 [`input-materials.md`](input-materials.md)。一句话原则：**缺什么一次说清，别边做边发现。**

产出：`source/` 里的原件，`manifest.json` 里的校验和。

## Phase 1 · 建档

```bash
python scripts/run.py new 试卷.pdf 答题卡.pdf 答案.pdf \
  --student 王小明 --grade 高三 --subject 物理 \
  --exam "高三第一次月考" --teacher 陈老师 --date 2026-10-25
```

`--service A` 是默认（高报附赠诊断，出报告即可）；`--service B` 用于月考/大型考试，
后面还要走纸质复做与变式，报告目标从"整卷"变成"锁定题组"。

产出：`work/<id>/source/`、`draft.json`（只有封面字段，`questions` 为空）。

## Phase 2 · 看图

```bash
python scripts/run.py pages work/<id> --max-width 1800
```

然后**真的去看** `pages/` 里的每一页——用宿主的看图能力逐张读，别用 `--text` 导出的
文字层代替。文字层能拿到题干，但拿不到：学生的勾选、划掉的选项、草稿区的式子、
老师打的叉、涂改痕迹。这些才是"原始作答"。

看的时候按这个顺序记：

1. 这一页是试卷还是答题卡？第几页？
2. 题号从几到几？有没有缺页跳到下一份文件？
3. 每题满分标了吗？有没有分项评分点？
4. 学生怎么答的——选项、式子、图像、空白？
5. 老师的批改符号是什么？得分写在哪？

> 如果某页糊到看不清一个数字，停下来问，不要"按上下文推"。试卷分析里一个字的差别
> 会改变整道题的对错。

产出：你自己脑子里的全卷地图；可写进 `review.md` 的"跳页 / 缺页"记录。

## Phase 3 · 核对

全卷过一遍，把"看得见的事实"落成 `questions[]`。

| 动作 | 写进哪 |
|---|---|
| 题号、题型、考点 | `id` `type` `topic` |
| 满分、得分 | `max` `score`（看不清 → `null`） |
| 原卷位置 | `sourcePage`，格式 `试卷第 2 页第 3 题 / 答题卡第 2 页` |
| 原始作答 | `studentAnswer`，照抄学生的选择/式子，不要转述 |
| 参考结果 | `referenceAnswer`，来自答案或你独立求解 |
| 评分点、评分来源 | `scoringPoints` `scoringSource` |
| 掌握状态 | `mastery`：掌握 / 部分掌握 / 未掌握 / 待核实 |

**整题还是小问？** 只选一种粒度。一道 12 分的大题拆成 3 个小问各 4 分是可以的，
但不要再加一行"第 4 题 12 分"。`validate` 会直接拦下来。

**分数拿不准的三种情况**：

- 有满分、有得分，但看不到评分细则 → 仍然记 `score`，`scoringSource` 写"教师按卷面批改"；
- 有满分，得分被涂改或两处矛盾 → `score: null`，`mastery: "待核实"`，在 `materialNotes` 里说明；
- 整页缺失 → 不要建这一题的记录，在 `materialNotes` 写清"第 X 页缺失，第 N 题未覆盖"。

## Phase 4 · 定位

只写**这一轮**要解决的问题，不是给全卷写墓志铭。

1. **做得好的**：哪几题拿了满分，靠的是什么能力。→ `strengthText`（≤75 字，带题号）
2. **本轮优先问题**：按"失分 × 可迁移性"挑 2–4 个，不是按失分从多到少排。→ `priority`
3. **卡在哪一步**：是没识别条件、建错模型、算错、还是写不出？→ `cause`
4. **初判错因**：写"会到哪一步、卡在哪、证据是什么"，等学生沟通时确认。

`priority` 的用法：`3` = 本轮必须先解决，`2` = 次之，`1` = 跟着做，`0` = 不用管。
报告第 3 页按 `priority` 降序、再按失分多少取前 4 题。**拿满分或待核的题不会被选。**

> 常见错误：把"粗心"当原因。粗心不是原因，是现象——写出他到底在哪一步把什么看错/
> 抄错/漏掉，才有可能训练。

## Phase 5 · 整理

逐题补满，然后跑结构检查：

```bash
python scripts/run.py check work/<id>
python scripts/run.py digest work/<id>
```

`check` 会告诉你还差什么（缺字段、字数超限、题型超过 6 类、附件题号不存在）。
`digest` 出 `analysis.html` / `analysis.md`——**这是给人校核的界面**，不是交付物。

写文案时的字数红线（超了渲染直接报错）：

| 字段 | 上限 | 用在哪 |
|---|---|---|
| `strengthText` / `weaknessText` | 75 字（约 3 行） | 第 2 页的优势 / 短板 |
| `directionText` | 50 字（约 2 行） | 第 2 页米色框 |
| `planFirst` / `planNext` / `planLater` | 110 字（约 4–5 行） | 第 3 页三栏复习安排 |
| `problemText` | 120 字（约 3 行） | 第 3 页诊断反馈·问题出在哪儿 |
| `nextStepText` | 150 字（约 3–4 行） | 第 3 页诊断反馈·接下来怎么做 |
| `typeComments[题型]` | 不卡字数，但每类只有 17–43 pt 高 | 第 2 页题型条下面的点评 |

报告是"扫一眼就懂"的版式，但**每块要写到 3–5 行**：先给结论，再给题号、失分、步骤
这些证据。只写两行、下面一大片白，家长会觉得钱花得不值；用"要努力""多练习"凑字
同样不行。

## Phase 6 · 备课

报告之外，老师上课要用的是这几样：

- **要问的问题**：每道重点题一个，问"当时怎么想的"，不是问"会不会"；
- **要讲的重点**：挑一道代表题，讲方法而不是讲这道题；
- **三段复习**：优先处理 → 随后巩固 → 后续专题与检查习惯，每段一个可验收的任务；
- **附件选题**：`appendixIds`，2 题最稳（5 页），最多 5 题；留空则自动取失分最重的两题。

## Phase 7 · 签核

```bash
python scripts/run.py approve work/<id> --all --reviewer 陈老师
```

这一步把 `reviewed` 置为 `true`，并在 `review.md` 追加一行记录。**签核是人的动作。**
签核前渲染出来的报告，所有分数都按"待核"统计（`已核 0/81 分`），这是故意的。

只想校核一部分？`--ids 1,3,5`。剩下的题报告里仍算待核。

## Phase 8 · 交付

```bash
python scripts/run.py render work/<id> --preview     # 五页 + 每页 PNG
python scripts/run.py render work/<id> --format compact --docx  # 两页家长版 Word
```

`--preview` 会把每页导成 PNG，自己看一眼再发出去：封面信息对不对、附件选的是不是那两道、
有没有哪段文字被压扁。

要进学生档案：打开教学工作台 → 试卷分析 → 「打开草稿」→ 选 `draft.json`。
工作台会做它自己的导入校验，然后把报告归档到该学生的「分析报告」资料里。

## 局部修订

只改几道题或几段文案时，不要重跑全流程：

1. 直接改 `draft.json` 里那几条；
2. `python scripts/run.py check work/<id>` 确认没弄坏结构；
3. `python scripts/run.py render work/<id>`。

`reviewed` 保持原样——除非改动的是题干、分值或结论，那要退回 `false` 重新签核。
（工作台的规矩是一样的：内容变了，旧签核自动失效。）

## 复做（B 类服务）

讲解后独立复做时，报告换成"复做分析"：同一套 `questions`，分数取复做结果，
题组要事前锁定。

1. 在 `draft.json` 里给目标题设 `target: true`，填好 `method`、`criticalPoints`、
   `teachingClass`（已教方法 / 已教知识待迁移）与 `teachingEvidence`；
2. `python scripts/run.py render work/<id> --kind retake --format final`；
3. 复做结果写在每题 `retake` 对象里（`score` `independent` `evidence` `reviewed` …）。

`standards.lock_scope()` 会拒绝"事后锁定"——已有复做结果的题不能再进锁定题组。

## 时间线（来自流程 V1.3）

| 节点 | 最迟 |
|---|---|
| 启动收卷 | 入组后 1 个工作日内确认学科并联系收卷；一/二模出分后 1 个工作日内 |
| 分析备课 | 必要资料补齐后 2 个工作日内，沟通前完成 |
| 学生沟通 | 报告完成后 7 个自然日内 |
| 反馈发送 | 沟通后下一个工作日内 |
| 后续检查 | 沟通后 7–14 个自然日内 |

对高报学生两周内出报告并沟通；对在读学员一周内。
